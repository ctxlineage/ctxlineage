# M2 — Report CLI + Call Anatomy View Implementation Plan

> **For Claude:** Execute task-by-task, in order. Every task ends with the full test suite passing and a commit. TDD. Tracking issue: #2.
>
> **⚠️ Phase gate:** Phase 1 (data backend, Tasks 1–6) proceeds autonomously. Phase 2 is an **interactive design session with the user** — do NOT start Phase 3 (frontend implementation) until the user has signed off on the visual design. This was explicitly requested.

**Goal:** `ctxlineage report --open` turns `.ctxlineage/events.jsonl` into a single self-contained HTML file showing, per call, what the context window contained (Call Anatomy), with token bars and a session sidebar.

**Architecture:** A pure-Python pipeline: JSONL → normalized report data (the JSON contract the frontend consumes) → injected into a prebuilt HTML template. Phase 1 builds the pipeline with a minimal placeholder template; Phase 3 replaces the template with the real React UI (frontend/ → `src/ctxlineage/static/`). Demo data comes from a keyless generator script so design/dev never needs an API key.

**Tech Stack:** `click` (CLI — chosen over typer: zero transitive deps, matches the minimal-deps principle), `tiktoken` (token estimation with a chars/4 fallback that keeps everything working offline), TS + React + Vite in Phase 3.

**Out of scope:** span/tag segmentation & lineage edges (M3 — but the data contract reserves fields), anthropic calls (M4), redaction (M4).

## Design decisions

- **Report data contract (consumed by the frontend, stable within M2):**

```json
{
  "report_version": 1,
  "generated_at": "<iso>",
  "stats": {"sessions": 2, "calls": 9, "errors": 1},
  "sessions": [{
    "id": "…", "started_at": "…", "ended_at": "…",
    "calls": [{
      "id": "…", "timestamp": "…", "provider": "openai", "api": "chat.completions",
      "model": "gpt-4o-mini", "stream": false, "duration_ms": 840.2,
      "error": null,
      "context_window": 128000,
      "usage": {"prompt_tokens": 913, "completion_tokens": 188, "total_tokens": 1101},
      "segments": [{"index": 0, "kind": "system", "role": "system",
                     "content": "…", "tokens_est": 182}],
      "input_tokens_est": 913,
      "output": {"content": "…", "finish_reason": "stop"},
      "call_stack": ["app.py:answer:42"]
    }]
  }]
}
```

  - `segments[].kind` is the role-based heuristic in M2 (`system|user|assistant|tool`); M3 adds tag-derived kinds (`rag_chunks` etc.) without changing the shape.
  - Token honesty: `usage` is the provider's real count; `tokens_est` are estimates. The UI derives bar *proportions* from `tokens_est` and shows *absolute* totals from `usage` when present.
- **Token estimation (`_report/tokens.py`):** try tiktoken (`encoding_for_model` → `o200k_base` fallback); any failure (no network, unknown model, import error) → `max(1, len(text) // 4)`. Never raises. Tests force the fallback so CI is hermetic.
- **Context windows:** small static `MODEL_CONTEXT_WINDOWS` map (prefix-matched, top OpenAI/Anthropic models only) → `null` when unknown. Honest "unknown" beats a wrong number.
- **Message extraction:** chat.completions → `request.messages` (string or content-parts list); responses → `request.instructions` (system) + `request.input` (string or item list). Output: non-stream `choices[0].message` / `output[].content[].text`; streamed → assembled `content["0"]` / `output_text`.
- **Demo data:** `examples/generate_demo_events.py` — keyless, deterministic, writes a realistic 2-session RAG/multi-turn `events.jsonl` (incl. one streamed call and one error call) via ctxlineage's own `EventWriter`. This is the design-session material and the normalization test fixture.
- **HTML embedding safety:** the JSON is embedded as `<script type="application/json">`; escape `</` as `<\/` to prevent script-tag breakout.

## Phase 1 — data backend (autonomous)

### Task 1: Demo event generator
`examples/generate_demo_events.py <dir>` + test running it via subprocess: every line validates against schema v1; contains ≥2 sessions, ≥1 streamed call, ≥1 error call.
Commit: `feat: add keyless demo event generator`

### Task 2: Token estimator
`src/ctxlineage/_report/tokens.py`: `estimate_tokens(text, model) -> int`. Tests: fallback path (monkeypatched import failure), empty text, proportionality. Add `tiktoken` + `click` deps to pyproject here.
Commit: `feat: add token estimator with offline fallback`

### Task 3: Normalization
`src/ctxlineage/_report/normalize.py`: `load_events(path) -> list[dict]` (skip malformed lines, count them) and `build_report_data(events) -> dict` per the contract. Handles: session grouping/sorting, chat + responses APIs, string and content-parts messages, streamed-assembled responses, error calls, missing usage.
Tests: handcrafted events covering each case + an end-to-end test over the demo generator output.
Commit: `feat: normalize events into report data`

### Task 4: Placeholder HTML renderer
`src/ctxlineage/_report/html.py`: `render(report_data) -> str` — minimal self-contained template (no CDN): embedded JSON + a few lines of inline JS rendering a plain per-call table. Explicit comment: replaced by the real UI in Phase 3.
Tests: output contains escaped JSON; `</script>` in prompt content cannot break out; valid standalone HTML (smoke).
Commit: `feat: render report data into self-contained placeholder HTML`

### Task 5: CLI
`src/ctxlineage/_cli.py` (click): `ctxlineage report [--dir .ctxlineage] [--out ctxlineage-report.html] [--open] [--json]`. `[project.scripts] ctxlineage` + `ctxl`. Friendly error (exit 1) when the events file is missing.
Tests: `click.testing.CliRunner` — happy path writes HTML, `--json` emits the contract, missing dir errors.
Commit: `feat: add ctxlineage report CLI`

### Task 6: Wrap-up phase 1
Full suite + lint green; generate a demo report end-to-end (`generate_demo_events` → `report`); push branch; open PR "M2 phase 1: report data backend (part of #2)". Merge after CI.
