# M2 Phase 3 — Production Report Frontend (server-rendered, no build step)

> **For Claude:** Execute task-by-task; every task ends with tests green and a commit. Tracking issue: #2. Architecture per PLAN.md §6 as amended 2026-07-16 (PR #18); visual spec = `docs/design/m2-mockups/` (signed off in the design session).

**Goal:** `ctxlineage report` emits the real two-view UI (Call Anatomy + Chain) as one self-contained HTML file, visually matching the approved mockups, replacing the phase-1 placeholder.

**Architecture:** The mockups *are* the frontend — productionize them. Assets live as plain files inside the package (`src/ctxlineage/_report/assets/`: `template.html`, `style.css`, `app.js`), inlined by `html.py` at render time (marker replacement; `__DATA__` substituted last so payload text can never re-trigger substitution). Everything client-side is hand-written vanilla JS operating on the embedded `report_version: 1` JSON. No node toolchain, no CDN. The server-side SVG layout engine from the drt reference is deferred to M3's Lineage Graph, where an arbitrary DAG actually needs it — M2's two views are DOM/CSS layouts with a measured SVG edge overlay.

**Key merges from the two mockups into one app:**
- Header: logo, stats, **view tabs (Calls | Chain)**, theme toggle (single localStorage key `ctxlineage-theme`, default follows `prefers-color-scheme`).
- Shared vocabulary: source-kind colors/labels (`app · instructions`, `user input`, `llm output (prev)`, `tool / MCP · <name>`, `tool defs`), step name from `call_stack[0]`, esc/fmt helpers — defined once.
- Calls view = call-anatomy mockup (sidebar: sessions→calls; detail: window bar, input segments, fn card with instructions, output).
- Chain view = chain mockup v3 (session sidebar; per-call `chips → fn → output` rows; adjacent edges by default, `↳ n` badge + click-to-fan-out with left-gutter routing; `↺ loop ×n` boxes for same-step chained runs).
- Mockup-only commentary ("M3 preview…") replaced with neutral product copy.
